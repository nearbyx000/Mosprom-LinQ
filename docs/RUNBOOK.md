# Запуск и эксплуатация SafeSight 0.3

## Быстрый запуск

Python 3.12, один серверный процесс. В Windows:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m scripts.preflight --mode demo
.\.venv\Scripts\python.exe run.py --mode demo --source synthetic
```

Linux/macOS: `python3 -m venv .venv`, далее `.venv/bin/python` вместо
`.\.venv\Scripts\python.exe`. Откройте `http://127.0.0.1:8000`; остановка Ctrl+C.
Не запускайте несколько workers/reload-процессов для одной физической камеры.

## Режимы

| Режим | Кадры | Инференс | Данные по умолчанию |
|---|---|---|---|
| `preview` | Камера/URL/файл | Выключен | `data/` |
| `demo` | Генератор при отсутствии source override | Цветовые фигуры, не нейросеть/TPU | `data/demo/` |
| `linq` | Камера/URL/файл | Только удалённый LinQ TPU | `data/` |
| `local` | Камера/URL/файл | Явный optional Ultralytics backend, не TPU | `data/` |

Для гарантированного синтетического демо укажите `--source synthetic`, даже если
в окружении ранее был `CAMERA_SOURCE`. Локальный режим не включается при сбое TPU.
`--data-dir data/my-session` изолирует журнал, evidence и outbox. Не используйте
рабочую папку данных для демонстрации. `--port 8010` помогает при занятом порте.

## Настоящая камера и зоны

```powershell
python run.py --mode preview --source 0
```

Индекс камеры, RTSP/HTTP URL и путь видеофайла поддерживаются. Windows использует
DirectShow, macOS AVFoundation, сетевой поток — FFmpeg с таймаутами. При обрыве
захват переподключается, поколение кадра меняется. Видео-файл зацикливается;
каждый повтор — новое поколение, а не независимое измерение качества.

Зоны задаются в `config/cameras.json` или `--config another.json`. Поддерживается
ровно одна камера на экземпляр сервиса и до 32 зон. Координаты x/y нормализованы
к `[0,1]`; полигон не должен пересекать себя. Принадлежность зоне проверяется
по нижней центральной точке bbox человека. Имена можно задавать по-русски;
ID — латиница, цифры, `_` и `-`. Неверная конфигурация отклоняется до запуска
потоков. После изменения зон перезапустите Web.

Зеркалирование физической камеры: `CAMERA_MIRROR=1` (default). Зоны рисуются на
том же обработанном кадре, что анализируется. Генератор demo не зеркалируется.
Параметры камеры: `CAMERA_WIDTH=640`, `CAMERA_HEIGHT=480`, `CAMERA_FPS=30`;
это запрос драйверу, не обещание фактических FPS.

## LinQ через JPEG Gateway

1. Подключите предусмотренный организаторами VPN в серверной среде.
2. Установите `python -m pip install -r requirements-linq.txt`.
3. Рабочие Gateway и `.tpu` не перезаписывайте. Если шлюзы уже работают,
   используйте их текущие уникальные `GATEWAY READY` routes.
4. Создайте `.env` из `.env.example`, задайте реквизиты брокера и routes.

```powershell
python -m scripts.preflight --mode linq --env-file .env --network
python run.py --mode linq --source 0 --env-file .env
```

`LINQ_JPEG_ROUTE` — primary COCO YOLOv8n. `LINQ_SV_ROUTE` — отдельный SV Gateway.
Без второго route работают только люди/зоны; отсутствие СИЗ не выводится из
отсутствия каски в COCO-выходе. Для прямого tensor-протокола вместо JPEG route
нужны официальный `tpu_pycloud_format`, `LINQ_LOGIN` либо `LINQ_PROGRAM_URI`.
Кодек не подменяется самодельным форматом. Шлюзы: [gateways/README.md](../gateways/README.md).

Preflight не открывает камеру и не публикует нейросетевых задач. Настоящий probe:

```powershell
python -m scripts.check_linq --env-file .env --image path/to/control.jpg --requests 1 --output data/probe-new.json
```

Этот probe использует прямой tensor transport. Для JPEG используйте
`python -m gateways.yolov8n.client --help` и актуальный route. Не запускать
много параллельных probes на общей TPU-инфраструктуре. Первый запрос — один.

## Как читать интерфейс

- **Stream clean / CV:** один непрерывный захват, переключение не открывает камеру
  заново. CV-рамки скрываются через 1.5 с от захвата; это последние результаты,
  не дорисованное движение между TPU-наблюдениями.
- **Warns:** зоны подтверждаются 3 последовательными наблюдениями, SV — 3 из 4
  действительных SV-наблюдений. Primary-only кадр не считается отрицательным SV.
  Последнее подтверждённое SV-предупреждение сохраняется в его собственном
  кратком окне свежести. Источник, время и кадр относятся к тому наблюдению.
- **Backlog:** запись остаётся после исчезновения текущего Warns. Фильтры журнала
  не меняют правила. Время показывается в часовом поясе браузера, на сервере
  хранится UTC. Фильтр даты переводится браузером в явный UTC.
- **Проверка оператора:** отметьте подтверждение/ложное срабатывание/повторный
  просмотр, при необходимости добавьте комментарий. Исходные confidence, время,
  JPEG и SHA256 не меняются; история решений сохраняется отдельно.
- **CSV:** выгружаются те же фильтры и лимит 50/100/500, максимум 500 событий;
  UTF-8 BOM для Excel, отметки оператора и хеш доказательства включены.
- **Тест JSON:** проверяет только отрисовку рамок, не распознавание и не журнал.

Нулевой счётчик при отсутствии свежего анализа не означает безопасность.
Confidence — оценка детектора, не вероятность юридической достоверности.
Трек — короткая геометрическая связь объектов, не идентификация человека.

## Данные и восстановление

```text
<data-dir>/events.sqlite       События и append-only история проверок
<data-dir>/evidence/*.jpg      Доказательные кадры
<data-dir>/event-outbox/*.json  Долговечные намерения записи при сбое БД
```

JPEG записывается через temporary file + fsync + atomic rename. Затем создаётся
outbox intent с SHA256 и metadata, после чего выполняется SQLite INSERT с
уникальным ключом. Если INSERT не прошёл, worker повторяет только запись в БД,
с backoff до 30 с. TPU-задача не повторяется. После перезапуска outbox восстанавливается.
Checksum mismatch или отсутствующий JPEG не превращаются в «успешное» событие.
Некорректный intent перемещается в `event-outbox/invalid/` с уникальным именем,
чтобы не блокировать остальные записи. Индикатор остаётся в состоянии ошибки;
JPEG и metadata сохраняются для ручной проверки. После проверки восстановите
согласованную пару JPEG/intent из резервной копии в отдельной тестовой папке.
Не удаляйте pending intents и evidence для устранения ошибки индикатора.

Если сам диск недоступен до создания intent, Warns остаётся видимым, ошибка записи
показывается отдельно, а следующая свежая детекция повторит попытку сохранения.
Для полной потери диска гарантия сохранения невозможна; внешний backup —
ответственность среды эксплуатации.

Схема legacy SQLite мигрируется транзакционно и добавочно. До первой миграции
создаётся `events.pre-v03-<unique>.sqlite`; старые строки получают source `legacy`.
Файлы JPEG не переименовываются. Для резервной копии работающей SQLite используйте
SQLite backup API, а не копирование одного файла при открытом writer. Сохраняйте
согласованно БД, `evidence/` и `event-outbox/`. Восстановление выполняйте при
остановленном сервере в отдельную папку и проверяйте на ней перед переключением.

## Доступ

По умолчанию сервис слушает только `127.0.0.1`. Для опциональной авторизации
задайте **оба** `SAFESIGHT_AUTH_USER` и `SAFESIGHT_AUTH_PASSWORD` в локальном `.env`.
HTTP API, evidence и WebSocket защищаются одним HTTP Basic доступом; `/health`
содержит только публичную liveness-информацию. Иностранный Origin отклоняется
для изменений и WebSocket. Для сетевого пилота нужен HTTPS reverse proxy;
HTTP Basic не заменяет TLS, роли, корпоративный SSO или защищённый аудит.
Встроенного управления пользователями и ролями в этой версии нет.

## Типовые сбои

| Наблюдение | Проверка / действие |
|---|---|
| API жив, видео нет | Индекс/URL камеры, права ОС, занятость устройства другим процессом |
| Видео есть, анализ выключен | Проверить выбранный mode; preview не делает инференс |
| Видео идёт, AMQP timeout | VPN, host/port, credentials, процесс Gateway; не перезапускать клиента многократно с неоднозначными задачами |
| SV unavailable / мало joined | Проверить второй route, `sv_error`, `sv_joined/sv_missed`, измеренный RTT и окно join |
| Pending recovery | Место/права диска, доступность SQLite, outbox и соответствие SHA256 JPEG |
| Не показываются старые live-рамки | Нормальное ограничение свежести; использовать сохранённый evidence |
| Каски плохо распознаются | Известное ограничение модели; не маскировать его повышением/понижением порога на test |

`/api/status` содержит счётчики/свежесть; `/api/summary` — реальные события за
24 часа и pending outbox. `/health` не является проверкой камеры/TPU.
Частота preview и RTT не являются точностью модели. Для оценки: [протокол](SAFETYVISION_EVALUATION.md).
