# Аудит SafetyVision, 25 октября 2026

Дополнение: выполнен [локальный ONNX-инференс двух моделей на 20 интернет-изображениях](INTERNET20_RESULTS.md).
Ниже сохранены результаты исходного аудита; внешняя минивыборка оценивается отдельно.

Патч подготовлен в `codex/safetyvision-accuracy` от локальной `WEB`.
Исходные незакоммиченные изменения в логике, pipeline и интерфейсе сохранены;
локальные модели, `.env`, доказательные кадры и рабочие TPU-программы не заменялись.
Развёртывание обновлённого Gateway на сервере не выполнялось.

## Найденные причины и исправления

| Узел | Результат аудита | Исправление |
|---|---|---|
| Контракт ONNX | `images float32 [1,3,640,640]`, `output0 [1,17,8400]`, 13 классов. Порядок совпадает с metadata. Отдельного objectness нет | Инструмент сравнения проверяет форму, тип и все имена классов до запуска |
| Preprocessing SV | Калибровщик `build_yolo_linq.py` из локального комплекта LinQ использует OpenCV INTER_LINEAR; SV Gateway использовал Pillow BILINEAR с другим уменьшением | SV использует OpenCV decode/resize, RGB, NCHW, `/255`, pad 114. Общий helper сохраняет исходный PIL default для YOLOv8n |
| Confidence / NMS | Multi-label позволял одному anchor возвращать противоположные классы | Лучший класс на anchor, затем NMS отдельно по классам. Близкий отрицательный/положительный ответ одного anchor означает неопределённость. Отсекаются NaN, вероятности вне `[0,1]`, отрицательные размеры и рамки, схлопнувшиеся при округлении |
| Координаты | Обратный letterbox в SV был принципиально корректен | Добавлена проверка конечности metadata и тест несимметричного letterbox с обратным преобразованием |
| Отсутствие каски | Любая отдельная `no_helmet` могла создавать тревогу без человека; противоположный `hardhat` игнорировался | Сопоставление с COCO person: центр в верхних 45% тела, пересечение ≥60% площади головы. При неоднозначном выборе человека — воздержание. Негатив должен превосходить каску на том же человеке хотя бы на 0.10 |
| Остальные СИЗ | Не было общей политики противоположных классов | Добавлена ассоциация СИЗ с людьми и подавление конфликтов для gloves, goggles, mask, vest. Новые виды тревог не включались |
| Трекинг головы | Независимый track головы терял подтверждение при небольших смещениях | PPE наследует person track. На одного человека и один тип правила учитывается не больше одного наблюдения кадра |
| Падение | Класс поддерживался локальными изменениями, но подтверждение могло склеивать далёкие по времени кадры | Сохранён независимый fall track, чтобы пропуск лежащего человека в COCO не блокировал сигнал. Добавлены ограничение временного разрыва и защита от повторов |
| Временное подтверждение | Требовались три подряд объединённых результата; кадровые пропуски мешали тревогам | Для SV — 3 попадания в последних 4 действительных SV-наблюдениях. Зоны сохраняют 3 последовательных попадания. Окно можно сделать строгим, установив 3 |
| Две модели | Готовность SV ограничивала отправку кадров в YOLOv8n | Независимые частоты отправки. Отсутствующий SV помечается `safetyvision_observed=False` и не считается отрицательной детекцией |
| Порядок / возраст | После join ожидания результат мог устареть; новый primary-only мог обогнать ожидающий SV | Возраст проверяется перед выдачей, порядок сохраняется в ограниченной очереди. Поздние, повторные и старые поколения отбрасываются. Очередь событий также проверяет возраст |
| Warns | Успешный YOLO мог скрывать отсутствие свежих результатов второго детектора | Отдельные `safetyvision_expected/fresh` в статусе и предупреждение в интерфейсе; тревоги зон остаются доступны |
| Автотесты | Общий запуск pytest конфликтовал с архивной копией `test_jpeg_gateway.py` | `pytest.ini` выбирает рабочие наборы тестов, включая Stage1 и dual integration |

Стандартный single-label путь соответствует [Ultralytics NMS](https://docs.ultralytics.com/reference/utils/nms/).
Не применяются sigmoid повторно, умножение на выдуманный objectness или преобразование RGB/BGR дважды.

## Проверка preprocessing и аппаратного пути

Локальный ONNX SHA256:
`a4d72ccc21a7552c0dbcb4610528372cbeb850c287cf580d9659df80ca8a6915`.

Два явно локальных CPU-прогона ONNX на трёх одинаковых JPEG из существующего
evidence сравнили Pillow и OpenCV. Средняя абсолютная разница входов `[0,1]`:
**0.002637, 0.002532, 0.002609**; максимальная разница class score по всем
anchor: **0.05779, 0.55797, 0.00778**. Количество рамок после одинакового нового
декодера: **[1,1,0] → [1,2,0]**. Это показывает влияние preprocessing на выход,
но не доказывает улучшение точности: изображения уже аннотированы, ground truth
каски/падения для них нет. Изображения не добавлены в репозиторий.

TCP `10.0.114.30:5672` доступен, но Pika получил
`IncompatibleProtocolError: StreamLostError: Transport indicated EOF` при
AMQP-согласовании. **Задачи инференса не отправлялись, результатов TPU нет.**
Потерю качества от квантования и реальные precision/recall/F1 измерить не удалось.
[Машиночитаемый диагностический отчёт](reports/safetyvision_diagnostic.json)
содержит хеши JPEG и `null` для отсутствующих измерений.

Парный benchmark сохраняет одинаковые float32 тензоры, raw выходы и хеши.
Он разделяет ошибку координат и class scores; agreement с ONNX явно отделено
от accuracy против ручной разметки. Такой подход согласуется с
[рекомендациями ONNX Runtime по диагностике квантования](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html).
Нельзя объяснять все ошибки квантованием до успешного парного прогона.

## Пороги, ограничения и альтернативы

Сохранён прежний рабочий порог 0.45 для приоритетных `no_helmet` и
`fall_detected`, положительные СИЗ имеют порог 0.40 для проверки противоречий.
Пороги отдельных классов можно переопределять. Они не объявлены оптимальными:
размеченного validation/test набора объекта пока нет. Повышение порогов без
такого набора могло бы скрыть реальные нарушения.

Консервативная ассоциация может пропустить голову без COCO person, частично
обрезанного человека и людей в тесной толпе. IoU-трекер остаётся простым и может
менять ID при перекрытии людей. Не вводится правило «нет рамки каски = нет каски»
или «горизонтальный bbox = падение». Новые виды PPE-тревог не включались.

[Автор модели](https://huggingface.co/ayushgupta7777/safetyvision-yolov8)
отмечает ограничения для мелких людей, взаимных перекрытий и видео с motion blur.
Его метрики не переносились в показатели SafeSight.

Порядок дальнейшего сравнения после разметки:

1. Если полный кадр ONNX пропускает маленькие головы, сравнить увеличенный ROI
   верхней части person с полным кадром на тех же случаях. Fall сохранять на
   полном кадре. ROI потребует отдельной проверки координат и аппаратной нагрузки.
2. Если ONNX даёт много ошибок на достаточно крупных головах, оценить
   специализированный helmet/no-helmet детектор с проверенным порядком классов
   и лицензией, сохранив SafetyVision для падений. Выбор делать по одинаковым
   held-out данным и ложным тревогам, а не по общей mAP из model card.
3. Для систематических ошибок конкретного ракурса/освещения — дообучение на
   данных площадки с hard negatives (наклон, сидение, телефон, светлые предметы,
   каски другого человека). Разделять capture sessions до нарезки кадров.
4. Если исходный ONNX приемлем, а TPU заметно хуже на тех же тензорах, сначала
   исправлять калибровку/квантование, затем повторить held-out оценку.

ROI, замена модели и дообучение не реализованы: измеренного выигрыша для них
пока нет. Подготовлены команды и защита от перезаписи для следующего эксперимента.
