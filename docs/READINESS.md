## Что подготовлено

- SafetyVision: OpenCV preprocessing в соответствии с калибровкой; проверенный
  порядок 13 классов; single-best-class decode, class-aware NMS и пороги по классам.
- Привязка СИЗ к человеку YOLOv8n, отказ от неоднозначного соответствия и
  противоречивых касок; три подтверждения из четырёх реальных SV-наблюдений.
- Объединение моделей только для одного кадра/поколения, отбрасывание старых
  и повторных результатов. Отсутствие SV-ответа означает неизвестное состояние СИЗ.
- Независимые capture/preview/inference/events workers; контролируемые очереди.
  YOLOv8n сохраняет основной person/zone путь и первоначальный PIL preprocessing.
- Durable JPEG + outbox для SQLite, уникальный event key, проверка SHA256,
  восстановление после сбоя и карантин повреждённых intents. Перед старой миграцией
  SQLite создаётся отдельная резервная копия. Абсолютная защита от потери диска не заявляется.
- Warns со ссылкой на кадр своего события, журнал с источником, CSV и отдельная
  история операторских решений. Опциональный HTTP Basic и запрет чужого Origin
  для изменений. Для удалённой эксплуатации нужен HTTPS; RBAC/SSO не реализованы.
- Изолированное 30-секундное DEMO без камеры/нейросети/TPU; явные mode banners.
  Quick start, preflight, воспроизводимый HTTP smoke и CI для трёх ОС.
- Исходники Gateway вынесены из ZIP в `gateways/`, старые установщики/probes —
  в `tools/legacy/`. Веса, SDK, данные, `.env` и архивы исключены из исходной поставки.

### Дополнительная проверка переполнения очереди

Повторный CI обнаружил редкий дубль события при медленной записи. Исправлено:
пропуск результатов сбрасывает только неподтверждённую непрерывность, сохраняя
уже зарегистрированный эпизод до реального выхода/истечения времени. Track ID
не переиспользуется после временного разрыва; ссылка на JPEG удаляется из
текущего соответствия после завершения эпизода, сам файл остаётся в Backlog.

В детерминированном fault-injection прежняя версия `4fdd7ff` записывала **2 события
на один непрерывный инцидент**, исправленная — **1**. Новые проверки также
исключают наследование JPEG прошлого эпизода. Полный прогон после исправления:
**112 passed** в обоих локальных окружениях. [Протокол](reports/storage_backpressure.json).

## Что измерено в компьютерном зрении

На одних и тех же **20 интернет-JPEG выполнены обе локальные ONNX-модели**.
Повтор после переноса канонических исходников дал те же результаты.
Это статическая диагностика, не независимый test цеха и не видеотревоги.

| Задача | TP / FP / FN, IoU ≥0.5 | Precision / Recall / F1 |
|---|---|---|
| YOLOv8n, person, проверенная разметка 19 кадров | 25 / 2 / 6 | 0.926 / 0.806 / 0.862 |
| SafetyVision, hardhat, 10 кадров | 8 / 0 / 2 | 1.000 / 0.800 / 0.889 |
| SafetyVision, no_helmet, 10 кадров | 0 / 1 / 12 | 0 / 0 / 0 |
| SafetyVision, fall, 10 кадров | 4 / 0 / 1 | 1.000 / 0.800 / 0.889 |

По наличию класса на изображении: no_helmet найден на **1 из 5** положительных,
fall — **4 из 5**; FP на пяти отрицательных кадрах каждого сценария — 0.
На 20 снимках исправления decoder/preprocessing **не изменили агрегатные метрики**.
В синтетической регрессии правил: до TP/FP/FN **6/7/2**, после **8/0/0**;
эти числа не являются точностью нейросети. Baseline-код и события включены в fixtures.

Отдельный helmet-кандидат отклонён: PPE F1 0.378 против 0.516 у SafetyVision.
Body ROI исследовательски повысил PPE F1 до 0.629 и no_helmet до 2 из 5
положительных изображений; head ROI не помог. ROI в production не включён:
мало данных, тот же набор использован для выбора гипотезы, нет аппаратного RTT
и независимого видео. [Подробный протокол альтернатив](MODEL_EXPERIMENTS.md).
[Исходники изображений, разметка и все ограничения](INTERNET20_RESULTS.md).

## Аппаратная проверка и сохранность

AMQP handshake до `10.0.114.30:5672` не прошёл; в последней диагностике —
`AMQPConnectorStackTimeout`. **Задач инференса не опубликовано, новых raw TPU
выходов и метрик квантования нет.** Подготовлены команды парного ONNX/TPU
сравнения, требования к калибровке и компиляция в новый каталог; на Windows с
LinQ SDK компиляция не выполнялась. [Команды](SAFETYVISION_EVALUATION.md).

Рабочие `.tpu`, routes, `.env`, реальные events/evidence не заменялись и не
очищались. Первоначальные незакоммиченные исходники сохранены в локальном
`data/defense-prep/checkpoint-20261025-0155/`. Удаление старых ZIP и весов из
Git выполнено **только через индекс**, файлы остаются на диске; их Git blob
hash совпал с исходным `c5a338e`. Новые SV/YOLO ONNX и TPU также остаются локальными.

## Решение о готовности

Поставку можно проверять как **пилот одной камеры с оператором**, воспроизводимым
демо, журналом и измерениями. Обещание надёжного no_helmet на реальном объекте
пока не обосновано. Перед промышленным пилотом нужны разметка видео площадки,
независимые контрольные эпизоды, реальные false alarms/camera-hour и парный
аппаратный прогон. HA, роли, корпоративное хранение и интеграции — отдельный этап.
