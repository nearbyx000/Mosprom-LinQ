# SafeSight / LinQ — камера, RabbitMQ и журнал

Ветка `WEB` объединяет просмотр камеры с готовыми правилами, зонами, SQLite и журналом из `LinQ-TPU`. Cloud-адаптер следует предоставленному notebook: `pika`, `tpu_pycloud_format.PyTask`, `serialize/deserialize`, exchange `tpu.direct`, routing key `input`, заголовки LinQ с URI программы, очередью ответов и ID задачи.

## Запуск камеры (Windows / PowerShell)

Python 3.12 рекомендуется. Из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py --source 0
```

Если в существующем окружении нет pip: `.\.venv\Scripts\python.exe -m ensurepip --upgrade`.

Открыть [Dashboard](http://127.0.0.1:8000/). Упрощённая страница камеры сохранена по адресу `/camera`. Остановка: Ctrl+C. По умолчанию включён режим `preview`: отправка на TPU отключена и явно показана в UI.

В macOS/Linux используются `python3 -m venv .venv`, `.venv/bin/python -m pip install -r requirements.txt` и `.venv/bin/python run.py --source 0`.

Сохранено исправление камеры из новых коммитов WEB: Windows открывает локальную камеру через DirectShow, macOS — через AVFoundation. Для сетевых URL используется FFmpeg с таймаутами открытия/чтения. Захват теперь общий для всех зрителей и освобождается при остановке сервера; отключение одного зрителя не закрывает камеру для остальных. Чтение устройства выполняется вне event loop FastAPI. Подключение камеры телефона через браузер не добавляется.

## Подключение настоящего LinQ через VPN

1. Подключите VPN на компьютере, где работает сервер, и проверьте доступность `10.0.114.30:5672`. Наличие камеры в браузере само по себе не означает, что на сервере настроен LinQ.
2. Установите зависимости и **пакет `tpu_pycloud_format` из окружения организаторов** в тот же Python, которым запускаете веб. Компилятор TPU и `pytpu.Device` веб-приложению не нужны. Не заменяйте пакет самодельным форматом сериализации.
3. Программа `yolov8n.tpu` должна уже находиться на стороне облака в `/auto/cache/<LOGIN>/yolov8n.tpu`. Локальная копия на Windows не делает файл доступным облачному воркеру. Веб не загружает программу в облако.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-linq.txt
# Если организаторы предоставили wheel, подставьте его реальный путь:
# .\.venv\Scripts\python.exe -m pip install C:\path\to\organizer_package.whl
.\.venv\Scripts\python.exe -c "from tpu_pycloud_format import PyTask, serialize, deserialize; print('format package OK')"
Copy-Item .env.example .env
```

В `.env` заполните `LINQ_LOGIN` либо полный `LINQ_PROGRAM_URI`; при необходимости — реквизиты брокера. Затем:

```powershell
.\.venv\Scripts\python.exe run.py --env-file .env --mode linq --source 0
```

Запускайте **один процесс uvicorn**: несколько процессов откроют несколько камер/соединений и увеличат нагрузку на общий TPU. По умолчанию один запрос одновременно и не более двух запросов в секунду. Максимум адаптера — 2 in-flight и 5 запросов/с; увеличивать лимиты следует только после согласования нагрузки на общий сервер.

Предобработка: BGR → RGB, letterbox 640×640, NCHW float32 / 255. Имена `images` и `output0`, формы `[1,3,640,640]` и `[1,84,8400]` проверены по локальному `models/yolov8n.onnx`. Адаптер принимает только COCO YOLOv8 и возвращает людей после decode/NMS; он не приписывает этой модели детекцию касок или падений. Для другой программы проверьте имена/формы отдельно.

Если конфигурация, пакет или сеть недоступны, Dashboard показывает причину в состоянии инференса; preview продолжает работать. Неисправное подключение до первой отправки повторяется с интервалом 5 секунд. При потере соединения с уже отправленными задачами инференс останавливается: факт исполнения неизвестен, автоматическая повторная отправка запрещена.

При таймауте запрос остаётся учтённым in-flight и новые отправки приостанавливаются до запоздалого ответа. Таймаут не отменяет задачу на TPU. Не перезапускайте многократно клиент при зависшем облачном воркере: это могло бы накопить задачи. Ответы с неизвестным ID, дубликаты, устаревшие и пришедшие не по порядку результаты отбрасываются и учитываются в счётчиках.

## Минимальная аппаратная проверка

Начните с одного запроса на известном изображении, затем измерьте серию:

```powershell
.\.venv\Scripts\python.exe -m scripts.check_linq --env-file .env --image C:\path\to\test.jpg --requests 1
.\.venv\Scripts\python.exe -m scripts.check_linq --env-file .env --image C:\path\to\test.jpg --requests 10 --output data/linq-probe.json
```

Команда использует только настоящий cloud-адаптер, выводит task ID, количество людей и сохраняет координаты/confidence, p50/p95 этапов и RTT. Нет fallback на локальную YOLO. Для контрольного изображения сравните рамки с ожидаемыми людьми. Синтетические тесты из CI не подтверждают работу TPU.

## Независимые частоты и измерения

- Capture worker непрерывно читает устройство в буфер **одного последнего кадра**. Драйверу запрашиваются 640×480 и 30 FPS; фактическая поддержка зависит от камеры. У старого кадра нет очереди перед инференсом. `CAP_PROP_BUFFERSIZE=1` — запрос драйверу, а не гарантия отсутствия аппаратного буфера.
- Preview worker независимо готовит JPEG до 30 FPS. MJPEG раздаётся всем зрителям из одного захвата; RabbitMQ и SQLite не участвуют в этом пути. Браузер читает MJPEG через fetch, декодирует JPEG в canvas, держит один ожидающий кадр и измеряет фактический FPS отрисовки.
- Inference worker обрабатывает RabbitMQ callbacks, отправляет свежий кадр только при свободном слоте и соблюдает лимит частоты. Все вызовы Pika выполняет один поток. Временная exclusive/auto-delete очередь ответов создаётся один раз на соединение; настройки общей входной очереди не меняются.
- Event worker получает результаты через ограниченную очередь, применяет существующие правила и подавление дублей, сохраняет **тот кадр, на котором получена детекция**, и записывает событие в SQLite. Переполнение очереди считается ошибкой потери наблюдений и сбрасывает подтверждение эпизода. Запись на диск не задерживает preview.

Live-видео содержит зоны. Рамки показываются на отдельном снимке последней детекции с номером кадра и возрастом результата: старые координаты не переносятся на текущее видео. Журнал, фильтры и уведомление о новых сохранённых событиях доступны в Dashboard. Уведомления сейчас внутри веб-страницы; внешние Telegram/email-каналы в исходном коде отсутствовали и здесь не настроены.

`/api/status` содержит FPS capture/preview/детекций, счётчики пропусков, in-flight, возраст результата и p50/p95 по последним максимум 300 измерениям этапа. Измерения используют `perf_counter`, чтобы не зависеть от грубого таймера Windows. FPS рассчитан по скользящему окну 10 секунд. Браузер отдельно показывает p50/p95 decode + draw и ожидание в своём буфере; физический вывод дисплея не измеряется.

**30 FPS preview — целевой режим, требующий проверки на реальной камере и в браузере. 30 FPS TPU не заявляются.** `rpc_round_trip` включает сеть, очередь и TPU. Присланный протокол не даёт отдельных длительностей TPU и сетевого/очередного ожидания, поэтому эти компоненты не выдумываются. Срок от чтения кадра до готовности JPEG не включает скрытый буфер самой камеры.

## Конфигурация и API

Источник и зоны задаются в `config/cameras.json`. `--source 0` или `CAMERA_SOURCE` переопределяет источник; можно указать HTTP(S), RTSP, видеофайл или `synthetic` для явно помеченного демо. Файлы видео при окончании открываются заново. `--mode demo` — синтетический цветовой детектор без TPU; `--mode local` — существующий Ultralytics backend, требующий отдельной установки и `SAFESIGHT_MODEL`.

`.env` загружается только при `--env-file .env`; обычные переменные shell также поддерживаются. Дополнительные параметры: `--host`, `--port`, `--reload`. Для камеры разрешите доступ настольным приложениям в настройках Windows/macOS. На удалённом сервере используется его камера, а не камера браузера.

- `/health` — liveness сервера, без проверки камеры/TPU.
- `/api/status` — состояние всех стадий и метрики.
- `/api/stream/cam-01`, `/video` — общий MJPEG.
- `/api/frame/cam-01` — текущий JPEG; HTTP 503, если свежих кадров нет.
- `/api/detection/cam-01` — снимок последней детекции, с заголовком номера кадра.
- `/api/events?camera_id=...&zone_id=...&violation_type=...&start=...&end=...` — SQLite-журнал.
- `/evidence/<filename>` — подтверждающий кадр; время события соответствует захвату исходного кадра.
- `/docs` — OpenAPI.

Модели, SDK, `.env`, записи и `data/` остаются локально. Сервер по умолчанию доступен на 127.0.0.1; авторизации нет, поэтому используйте доверенную сеть.

## Проверки без оборудования

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Проверяются готовые правила/SQLite, API, latest-frame буфер, preview при медленном fake backend, evidence, точные RabbitMQ-заголовки, task ID, лимит запросов, таймауты, порядок ответов, letterbox/NMS и остановка потоков. Это проверки интеграции, а не аппаратный бенчмарк LinQ.
