# SafeSight — веб-интерфейс камеры

Ветка `WEB` проекта Mosprom-LinQ: FastAPI-сервер и русскоязычная страница с MJPEG-видео, состоянием подключения и кнопкой переподключения. Источник — USB/встроенная камера компьютера, на котором запущен сервер, либо HTTP(S)/RTSP-камера.

Текущий MVP показывает видео с сервера или принимает его от браузера телефона.
YOLO, LinQ TPU, RabbitMQ, база событий и авторизация пока не подключены.
Файлы из локальных папок `models/` и `tpu_framework_*/` для запуска веба не нужны и исключены из Git.

## Камера телефона → сервер → просмотр на компьютере

Телефон и компьютер должны иметь доступ к одному серверу. На телефоне требуется
HTTPS с сертификатом, которому доверяет телефон: обычный HTTP по локальному IP
не даёт браузеру доступ к `getUserMedia`. Исключение localhost относится только
к самому устройству, а не к IP компьютера. См. [документацию getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).

Запуск с вашим сертификатом для LAN-адреса или домена сервера:

```powershell
.\.venv\Scripts\python.exe run.py --host 0.0.0.0 --port 8443 --ssl-certfile certs/server.pem --ssl-keyfile certs/server.key
```

Сертификат должен соответствовать адресу, который открывается на телефоне.
Проект не устанавливает корневые сертификаты и не меняет доверие системы.
Можно также использовать уже настроенный HTTPS reverse proxy с поддержкой WebSocket.
Для такого proxy запускайте Uvicorn на loopback; он должен сохранять Host запроса.
Проверьте доступность выбранного порта в частной сети.

1. На телефоне откройте `https://<адрес-сервера>:8443`.
2. Выберите **«Камера этого устройства»**, затем основную или фронтальную камеру.
3. Нажмите **«Подключить»** и разрешите камеру в браузере.
4. На компьютере откройте тот же сервер, выберите **«Трансляция с телефона»**
   и нажмите **«Подключить»**.
5. **«Остановить»** выключает камеру телефона и прекращает передачу.

Камера запрашивается только после нажатия кнопки. Микрофон не используется.
При уходе со страницы/смене источника видеотреки останавливаются. Держите страницу
на телефоне открытой: мобильная ОС может приостановить камеру в фоне или при блокировке.

Браузер передаёт JPEG по WebSocket `/phone/publish`, сервер раздаёт MJPEG через
`/phone/video`. Хранится последний кадр, записи на диск нет. Длинная сторона кадра
ограничена 640 пикселями, частота не превышает 10 кадров/с. Следующий кадр отправляется
после подтверждения предыдущего, поэтому очередь загрузок не растёт.
Поддерживается один телефон-источник и несколько зрителей его потока.
После отключения телефона последний кадр удаляется; для нового источника зритель
нажимает «Подключить». Отдельный серверный `/video` по-прежнему рассчитан на одного зрителя.

Максимум сообщения 1 MiB. Сервер проверяет JPEG и размеры до декодирования,
перекодирует изображение и отклоняет второй источник и WebSocket с чужим Origin.
Эта проверка не заменяет авторизацию: используйте доверенную частную сеть.
Публичный доступ требует отдельного ограничения доступа на HTTPS proxy.

## Быстрый запуск в Windows (PowerShell)

Нужен Python 3.10 или новее; проверено на Python 3.12. Из корня репозитория:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

Активация окружения и изменение ExecutionPolicy не требуются. Если Python установлен без `py`, используйте `python -m venv .venv`. Для уже существующего окружения без pip сначала выполните `.\.venv\Scripts\python.exe -m ensurepip --upgrade`.

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Остановить сервер: **Ctrl+C** в терминале. Для другого порта: `run.py --port 8080`; для автоматической перезагрузки при разработке: `run.py --reload`.

Разрешите использование камеры настольными приложениями в **Параметры → Конфиденциальность и безопасность → Камера**. Если камера занята другим приложением, закройте его и нажмите «Подключить заново».

В Windows локальная камера открывается через DirectShow; в macOS — через
AVFoundation. Сетевые HTTP(S)/RTSP-источники используют стандартный backend OpenCV.
При закрытии видеопотока устройство освобождается. Если до этого работал отдельный
просмотр камеры, остановите его перед запуском этого приложения.

## macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

В macOS разрешите камеру своему терминалу в **System Settings → Privacy & Security → Camera**. В Linux проверьте доступ к устройству `/dev/video*`.

## Настройка камеры

По умолчанию используется камера `0`, изображение зеркалируется. Переменные окружения задаются **до запуска** сервера. `.env.example` содержит примеры; `.env` автоматически не загружается.

Windows:

```powershell
$env:CAMERA_SOURCE = '0'
$env:CAMERA_MIRROR = '1'
.\.venv\Scripts\python.exe run.py
```

Сетевая камера или телефон с приложением IP Webcam в той же сети:

```powershell
$env:CAMERA_SOURCE = 'http://192.168.1.105:8080/video'
$env:CAMERA_MIRROR = '0'
.\.venv\Scripts\python.exe run.py
```

Подставьте реальный адрес своего видеопотока. Для macOS/Linux используйте `export CAMERA_SOURCE='http://...'` и `export CAMERA_MIRROR=0`. Поддержка конкретного сетевого формата зависит от OpenCV/FFmpeg. Для возврата к локальной камере задайте `CAMERA_SOURCE=0`.

## Проверка работы

- `/` — страница просмотра.
- `/health` — работоспособность сервера: `{"status":"ok"}`; доступность камеры не проверяет.
- `/docs` — интерактивная документация API.
- `/video` — MJPEG; возвращает HTTP 503, если камера недоступна или не отдаёт первый JPEG-кадр.

При ошибке на странице отображается сообщение и кнопка повторного подключения.
Для камеры сервера используйте одну вкладку просмотра одновременно. Режим
«Камера этого устройства» передаёт камеру браузера, в том числе с телефона.

Сервер слушает `127.0.0.1`. Для доступа из локальной сети можно указать `run.py --host 0.0.0.0`. Доступ к видео не защищён авторизацией: используйте доверенную частную сеть и не публикуйте порт в интернете.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют страницу, статику, API, MJPEG, ошибки камеры и освобождение устройства без физической камеры. GitHub Actions запускает их на Windows, macOS и Linux.

Для браузерной логики также выполните `node --test tests/camera.test.cjs` (Node.js 22+).
Проверяются ограничение загрузки подтверждениями, остановка видеотреков,
отказ от запроса камеры по небезопасному HTTP и позднее разрешение после остановки.
Это автоматические проверки с тестовыми объектами; физический телефон ими не эмулируется.

## Структура

```text
app.py                      # API, открытие камеры и MJPEG
run.py                      # Запуск с --host, --port и --reload
web/                        # HTML, CSS, JavaScript
tests/test_api.py           # Тесты без оборудования
.github/workflows/tests.yml # CI
.env.example                # Примеры переменных окружения
requirements.txt            # Зависимости сервера
requirements-dev.txt        # Дополнительные зависимости тестов
```

Не добавляйте в Git `.venv`, пароли камер, локальные `.env` и записи видео. Следующий этап — общий захват кадров для нескольких зрителей и подключение инференса LinQ TPU / YOLO.
